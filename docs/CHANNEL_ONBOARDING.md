# 从「个人收款码」切到「有官方回调的正规通道」

## 0. 先说结论：代码侧已经铺好了

支付中心一开始就是按「多渠道 + 统一抽象」设计的，**正规渠道的下单、查单、关单、退款、账单下载、回调验签适配器全部已实现**，后台也有配置页。个人收款码只是其中一个渠道（`personal_qr`），不是架构限制。

所以"切到有回调的通道"这件事，**不需要改业务系统代码，也不需要改支付中心代码**，剩下的是两件外部工作：

1. **入网**（线下/线上申请，拿商户号与密钥）
2. **配置**（后台填参数 + 渠道后台填回调地址）

已实现适配器：`wechat`（V3：JSAPI/NATIVE/APP/H5/面对面）、`alipay`（当面付：PC/NATIVE/APP/WAP）、`unionpay`（PC/NATIVE/WAP/APP）。

## 1. 入网路径怎么选

| 通道 | 门槛 | 费率 | 结算 | 是否给我方 API 回调 | 适用 |
| --- | --- | --- | --- | --- | --- |
| **微信支付小微商户** | **无营业执照也可**（身份证 + 银行卡 + 门店照） | 0.38%~0.6% | T+1 到个人银行卡 | ✅ 有 | **个人码升级首选** |
| 微信支付普通商户 | 营业执照 / 个体户执照 | 0.6% | T+1 到对公/法人账户 | ✅ 有 | 有主体、量较大 |
| 支付宝当面付 | 个体户执照（或个人商家） | 0.6% | 次日到支付宝余额/卡 | ✅ 有 | 与微信配套 |
| 银行聚合收款码 | 依银行 | 0.2%~0.5% | 到银行卡 | ⚠️ 多数只有静态码 + 商户后台，**无 API** | 只收款、不要求回调时 |
| 持牌聚合支付（收钱吧等） | 服务商开通 | 0.38%~0.6% | 服务商结算 | ✅ 有 | 想一次接多家钱包 |

> 选通道时**唯一硬指标**：对方是否提供「支付结果异步通知 API」。没有回调的，就退回个人码 + 监控器模式（见 `docs/PERSONAL_QR_MONITOR.md`）。

## 2. 入网材料清单

**微信小微商户**（微信支付商户平台 / 服务商代为进件）：
- 经营者身份证正反面
- 结算银行卡（本人）
- 门店门头照 + 经营场景照
- 手机号、经营类目、经营地址

**支付宝当面付**（支付宝商家中心 → 产品中心 → 当面付）：
- 营业执照（个体户即可）或个人商家身份认证
- 法人/经营者身份证、结算账户
- 网站/App 信息（用于创建应用拿 APPID）

**银联**：由收单机构/银行进件，拿 `merId` + 签名证书（certId、私钥、验签公钥证书）。

## 3. 后台配置（支付中心侧）

「渠道管理 → 新增渠道配置」，按渠道填：

| 渠道 | 必填字段 | 说明 |
| --- | --- | --- |
| 微信支付 | 商户号 mchId（10 位） | 商户平台的商户号 |
| | AppId（wx 开头 18 位） | 公众号 / 小程序 AppID |
| | 证书序列号（40 位十六进制） | `apiclient_cert.pem` 的序列号 |
| | APIv3 密钥（32 位） | 商户平台「API 安全」设置，用于回调解密 |
| | 商户私钥 PEM | `apiclient_key.pem` 全文（含 BEGIN/END 头尾） |
| | 微信平台证书 PEM | **生产必配**：否则回调验签会被跳过（适配器会告警） |
| 支付宝 | 合作者 PID（16 位）、应用 APPID（16 位） | 开放平台应用 |
| | 签名类型 RSA2、应用私钥、支付宝公钥 | 密钥工具生成 |
| 银联 | merId（15 位）、certId、签名私钥、验签公钥证书 | 收单机构下发 |

配置项要点：
- `isSandbox`：**上线必须关掉**（沙箱）。
- `enabled`：启用。
- `priority`：同渠道多商户号时的选路优先级，数字大的优先。
- `scene`：留空表示全场景。

## 4. 回调地址（填到渠道商户后台）

支付中心侧已固定好路由，把下面地址填进渠道商户平台的「支付结果通知 URL」：

```
支付结果：  https://{对外域名}/api/v1/notify/wechat/pay
            https://{对外域名}/api/v1/notify/alipay/pay
            https://{对外域名}/api/v1/notify/unionpay/pay
退款结果：  https://{对外域名}/api/v1/notify/{channel}/refund
```

`{对外域名}` = 后台「系统设置 → 站点信息 → 对外访问地址」（`site.baseUrl`）。

要求：
- 必须 **HTTPS + 已备案域名**，微信不接受 IP 与非标端口。
- 该地址由支付中心自己验签（微信 V3 用平台证书验签 + AES-GCM 解密，支付宝 RSA2 验签），业务系统不参与。

## 5. 切换：业务系统零改动

1. 业务系统下单时 **channel 保持 `auto` 或不传**（不要写死 `personal_qr`）。这是关键前提。
2. 后台给目标应用开通渠道：`allowChannels` 加入 `wechat` / `alipay`。
3. 自动路由规则：`已接入渠道 ∩ 该应用已开通 ∩ 场景(tradeType)匹配` → 取 `priority` 最高者。
4. 灰度：先给 1~2 个应用加 `wechat`，观察回调与通知正常，再全量。
5. 个人码不要立刻删：把 `personal_qr` 的 priority 调低，作为正规通道故障时的降级兜底。

⚠️ **生产环境必须确认的开关**：`DEFAULT_CHANNEL_MODE`。
`channel.service.resolveChannel()` 里有一句：默认值为 `sandbox` 时，`auto` 路由会**直接返回 mock 渠道**（避免选到"已配置但未联调"的真实渠道）。上线前需在环境里设为 `production`，否则配了真渠道也走不到。

## 6. 上线核验清单

- [ ] `DEFAULT_CHANNEL_MODE=production`，渠道配置 `isSandbox=false`
- [ ] 回调地址已在渠道后台配置，且是 HTTPS
- [ ] 真实下单 1 分钱 → 支付 → 订单变 `SUCCESS` → 业务系统收到通知并返回 200（「通知管理」里看状态）
- [ ] 关单：未支付订单超时自动关闭（定时任务每分钟扫）
- [ ] 退款：发起退款 → 渠道异步回调 → 退款单 `SUCCESS`
- [ ] 对账：下载渠道账单跑一次对账，差异为 0
- [ ] 平台证书已配（微信），日志里不再出现"跳过验签"告警

## 7. 过渡期方案：个人码的自动化与自助确认

入网审批通常要 1~3 个工作日，过渡期可继续用个人码，并且不必全靠人工：

- **监控器自动上报**：`POST /api/v1/open/qr/payment-report`（见 `docs/PERSONAL_QR_MONITOR.md`）
- **商户自助确认**：`POST /api/v1/open/pay/confirm-paid`

```json
{
  "payOrderNo": "P20260920...",
  "paidAmount": 100.00,
  "channelTxnId": "微信账单里的交易号",
  "payerAccount": "张**"
}
```

设计上的两道防线：
1. **只允许 `personal_qr` 渠道**：有官方回调的渠道禁止人工置成功（否则等于可以凭空把没收到钱的订单变成已支付）。
2. **必须传 `paidAmount` 且与应付金额一致**：不一致直接拒绝；确属少付/多付需显式传 `allowDiff=true`，差异写入 `channelRaw` 留痕并告警日志。

重复调用安全：`markPaid` 是带状态条件的原子更新，已 `SUCCESS` 的订单返回 `updated:false` 且不会重复通知。

## 8. 一句话建议

日收款量起来后优先入 **微信支付小微商户 + 支付宝当面付**：无执照也能入、有官方回调、可对账、可退款，而支付中心这边只是"后台加一条渠道配置"的事——业务系统一行代码都不用改。
